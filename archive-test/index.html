Method and limitations

  • Canonical source: annual Markdown files in the linked repository. posts.csv contributes publication dates, titles, subtitles, audience and publication status when a match can be made.
  • Parsing: the page looks for dated title lines and post/day headings. Unusual formatting can cause a post to be missed or a boundary to be imperfect. Compare the parsed count with the archive's own annual totals.
  • Word count: approximate body-word count. Markdown syntax, image URLs and link destinations are removed, while visible link text remains.
  • Topics: transparent keyword rules. A tag means a term or related phrase appeared, not that it was the post's main argument.
  • Entity index: heuristic name candidates from repeated capitalized phrases. Nicknames, aliases, irony, transliteration variants and outlet names require human review. The app intentionally does not merge identities automatically.
  • Freshness: refresh the page after updating a yearly Markdown file. If the raw file is unavailable or parsing fails, the status area identifies the affected year.
  • Text-only scope: photos, maps, illustrations, screenshots and other visual evidence are not indexed by this tool.

For a rigorous, publishable index, the candidate list should be curated in a separate alias register with canonical name, aliases, type, confidence and supporting post references.
